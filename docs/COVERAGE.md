# 相对三款原软件的功能覆盖

作者原先三开 AdGuard DNS、FLClash、GKD，被 Android「只能一个 VPN」卡住，才做本应用。背景和 **0.4.76 已实现清单** 在 [README](../README.md)。这里只回答：日常路径覆盖了三家多少。

对照对象：

- AdGuard（Android）里用户实际在用的 **DNS 保护**
- FLClash（Clash Meta / mihomo 客户端）
- GKD（开屏/弹层订阅）

图例：**覆盖** = 日常能顶上；**部分** = 有同类能力但浅；**不做** = 明确不做或做不到。

覆盖度按「那款软件里、用户天天会碰到的路径」估，不是按官方功能树条数。条数一比，我们肯定输——人家各做十年了。

| 对照 | 日常路径覆盖（约） | 整包功能覆盖（约） | 一句话 |
| --- | --- | --- | --- |
| AdGuard | **70%**（只开 DNS 保护、不开 HTTPS 过滤） | **25–30%** | 拦域名像；拦 HTTPS 页内广告不像 |
| FLClash | **70–75%**（订阅、节点、规则、按 App） | **45–50%** | 能科学上网和分流；配置中台偏瘦 |
| GKD | **70%**（默认订阅 + 开屏） | **40%** | 能点开屏；不能审快照、不能当规则编辑器 |

合成之后的额外价值：三套能力共用 **一个 VPN 坑**，这是三家官方 App 加起来也给不了的。

---

## 1. AdGuard

用户原话场景：只用 DNS 保护，有时发现微信公众号广告也被拦。那是 AdGuard 完整版（或 HTTPS 过滤）的副作用，不是纯 DNS。

### 1.1 覆盖

| 能力 | 状态 | 本项目怎么做 |
| --- | --- | --- |
| DNS 保护 / 本机 DNS 过滤 | 覆盖 | `WuadDnsServer`，广告域回空地址 |
| 广告主机名单 | 覆盖 | anti-AD 默认；AdRules / 自定义订阅 |
| 跟踪名单 | 部分 | Peter Lowe 预置但默认关（和 anti-AD 重叠太多） |
| 自定义拦截 / 放行 | 覆盖 | 设置里一行一个域名，放行优先 |
| 按 App 关闭过滤 | 覆盖 | 应用列表「DNS 不启用」 |
| 上游：明文 / DoH / DoT | 覆盖 | 默认 `223.5.5.5`，可加阿里 DoH、CF、自定义 |
| IPv6 解析 | 覆盖 | AAAA 同步拦或转发 |
| 查询日志 | 覆盖 | 日志 → DNS，带应用名（能归因时） |
| 过滤统计 | 部分 | 首页今日拦截数，没有按公司/类别的大盘 |
| DNS-only 隧道（不代理全部流量） | 覆盖 | 分流关、DNS 开：只路由 DNS 地址 |
| 与私人 DNS 冲突提示 | 覆盖 | `DnsProbe` |

### 1.2 不做 / 弱

| 能力 | 状态 | 原因 |
| --- | --- | --- |
| HTTPS 过滤 / 用户证书 | 不做 | 不做中间人 |
| 微信公众号、同域 HTTPS 页内广告 | 不做 | 域名合法，内容在 TLS 里 |
| AdGuard 过滤语法、元素隐藏、脚本注入 | 不做 | 只有域名集合 |
| 隐身模式、反指纹、CNAME 剥离 | 不做 | |
| 钓鱼 / 恶意网站库 | 不做 | |
| 家长控制、HTTPS 按应用精细策略 | 不做 | |
| AdGuard VPN / 浏览安全套件 | 不做 | |

**结论：** 把 AdGuard 当成「系统 DNS 去广告」用，日常名单 + 上游 + 日志这条线大概七成。把 AdGuard 当成「App 里广告也抠掉」用，本项目覆盖不了，那是 HTTPS 过滤的活。

## 2. FLClash / mihomo

### 2.1 覆盖

| 能力 | 状态 | 本项目怎么做 |
| --- | --- | --- |
| MetaCubeX mihomo 内核 | 覆盖 | 官方 so v1.19.33，不裁剪 |
| TUN / gvisor | 覆盖 | 继承 VpnService fd，`auto-route=false` |
| IPv6 路由 | 默认关 | `TUN_IPV6=false`，不声明 `::/0`；避免 gvisor 直连 v6 失败 |
| Clash / mihomo YAML 订阅 | 覆盖 | `SubFetch`，FLClash 一类 UA |
| 多订阅合并进 PROXY | 覆盖 | 设置里可加多份 |
| 节点列表（分流关着也显示） | 覆盖 | 读本地订阅文件 |
| 延迟测速 / AUTO | 覆盖 | 内核 API，空格节点名按官方编码 |
| 规则 / 全局 / 直连 | 覆盖 | `Prefs.mode` |
| GEOSITE / GEOIP | 覆盖 | MetaCubeX geo 四件套 |
| 自定义规则（DOMAIN / IP / PROCESS…） | 覆盖 | 分流页可增改 |
| 按 App 直连 / 代理 / 不进隧道 | 覆盖 | `PROCESS-NAME` + exclude |
| fake-ip + dns-hijack | 覆盖 | `198.18.0.1/16`，53 UDP/TCP |
| sniffer HTTP/TLS/QUIC | 覆盖 | 官方同款端口 |
| 连接日志 | 部分 | 扫 `mihomo.log`，不是完整 Connections 面板 |
| 规则集订阅（Loyalsoldier） | 部分 | 预置 reject/proxy/direct，默认关 |

### 2.2 不做 / 弱

| 能力 | 状态 | 原因 |
| --- | --- | --- |
| 多配置文件 / Profile 切换 | 不做 | 只有一份工作配置 |
| Override、Mixin、脚本 | 不做 | |
| 内核 Web UI / Meta 面板 | 不做 | API 只给本机节点和测速 |
| 代理组策略细调（url-test 参数、fallback 链） | 部分 | 固定 PROXY + AUTO |
| `auto-detect-interface` | 不做 | Android 14+ 不稳，改写网卡名 |
| x86 / 32 位 | 不做 | 只 arm64 |
| 磁贴、分应用一键模式、备份恢复 | 不做 | |
| 流量统计大盘、连接实时表 | 部分 | 有日志，没有 FLClash 那种连接页 |

**结论：** 填机场、选节点、国内直连海外走代理、按 App 分流，这条日常路径大约七成到七成五。当配置中台或桌面 Clash Verge 用，差得远。

## 3. GKD

### 3.1 覆盖

| 能力 | 状态 | 本项目怎么做 |
| --- | --- | --- |
| json5 订阅 | 覆盖 | `GkdParser` + `Json5Lite` |
| 官方选择器（右向左、关系符、括号） | 覆盖 | `GkdSelector` / `SelectorParse` |
| `matchAnyApp` 默认 true | 覆盖 | `GkdScope` |
| 桌面 / 系统应用默认不匹配 | 覆盖 | `matchLauncher` / `matchSystemApp` 默认 false |
| 开屏分类默认开 | 覆盖 | `GkdCats` 11 类，仅开屏默认开 |
| 其余官方分类 | 覆盖 | 青少年 / 更新 / 评价 / 通知 / 权限 / 局部 / 全屏 / 分段 / 功能类 / 其他，默认关 |
| 按 App 忽略 | 覆盖 | 应用列表 |
| 点击 + 手势补点 | 覆盖 | `performClick` / `dispatchGesture` |
| 冷却、同组限次 | 覆盖 | 20 秒、组计数 |
| 国内镜像回退 | 覆盖 | ghfast → gitmirror → jsdelivr → ghproxy |
| 点击日志 / 今日 KPI | 覆盖 | 与日志「点击」同口径 |
| activity / 选择器作用域 | 部分 | 按订阅字段执行，没有快照对照 |

### 3.2 不做 / 弱

| 能力 | 状态 | 原因 |
| --- | --- | --- |
| 快照捕获与审查 | 不做 | 不做规则生产工具 |
| 选择器调试台 / 属性查看 | 不做 | |
| 网页规则 / CSS | 不做 | |
| 多订阅并行管理 | 部分 | 一个主 URL + 镜像，不是多仓库工作区 |
| 导入导出、订阅商店 | 不做 | |
| 全部高级 action（长按、滑动序列、返回键策略） | 部分 | 以点击为主 |
| 和官方 100% 选择器边角 | 部分 | 未声明的选择器直接跳过，不硬猜 |

**结论：** 装上默认订阅、只开开屏，淘宝/京东这类「选择器能点到」的路径大约七成。当 GKD 本体做规则、审快照，覆盖大约四成。有的开屏是 App 自己倒计时关的，两边日志都可以是空的，那不算漏点。

## 4. 三家加起来，本项目多出来的和少掉的

### 多出来的

- 一个 VPN 坑同时活着 DNS + 分流，GKD 还在。
- 首页把三套开关和今日数字摊开，点进去就是对应日志。
- 侧载 ColorOS 引导（限制设置无障碍、耗电、锁定任务）。

### 少掉的（有意）

- HTTPS MITM
- 统计 SDK / 账号 / 云同步
- 微信 / QQ / 飞书 DNS 私货白名单
- 为个别 App 写死的跳过规则（一律跟订阅走）

### 建议对外怎么写，别怎么写

可以写：

> 侧载环境下，把 AdGuard DNS 保护、FLClash 分流、GKD 开屏跳过的常用路径合成一个 App。

不要写：

> 完整平替 AdGuard / FLClash / GKD。

那是骗人。完整平替做不到，合成才是这仓库存在的理由。

## 5. 给 Release / README 的短表

| 用户原软件用法 | 能不能迁过来 | 迁完注意 |
| --- | --- | --- |
| AdGuard 只开 DNS 保护 + 订阅名单 | 能 | 关掉私人 DNS；公众号页内广告不要指望 |
| AdGuard 开了 HTTPS 过滤 | 不能 | 需要中间人，本项目不做 |
| FLClash 一份订阅 + 规则模式 | 能 | 先更新 geo，再开分流 |
| FLClash 多配置、覆写、面板 | 不能 | 继续用 FLClash，但 VPN 不能和本应用同时开 |
| GKD 默认订阅只开开屏 | 能 | ColorOS 限制设置里放行无障碍 |
| GKD 自己写规则 / 审快照 | 不能 | 规则仍去 GKD 官网或订阅仓库改 |
